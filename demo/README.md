# Tinderbox Demo

方案里核心链路的最小可运行实现。**不是产品，是"这套设计到底成不成立"的实物证据。**

当前状态：**12/12 自测通过**，真 LLM 提炼 + 真 LLM 判定，输出可复现；
无 key 时自动退回规则提炼，且**精确优先**（宁可少记，不灌垃圾）。

## 跑

> 本机 PATH 上的 `python` 是应用商店占位符，必须用下面这个解释器。

```powershell
$py = "C:\Users\pelican\.dsh\dsh-runtimes\dsh-primary-runtime\dependencies\python\python.exe"

& $py demo\run_demo.py        # 八步走查，写 demo/out/run.log
& $py demo\run_complement.py  # 补充记忆测试（先跑上一条）
& $py demo\selftest.py        # 11 项不变量，全过返回 0
& $py demo\run_offline.py     # 三件事的证据：断网写入 / 异步精修 / Markdown 往返
& $py demo\web.py             # 看板 http://127.0.0.1:8777（首次访问要令牌）
```

零第三方依赖，Python 3.10+。LLM 可选：`demo/.env` 里填 key 就用真模型，没有 key 自动退回规则版。

## 看板有四个视图

| 视图 | 回答什么问题 |
|---|---|
| **搜索**（默认，输入即搜） | 有没有相关的记忆——**一次给全**，旧版本划掉并标灰 |
| **演变** | 这件事怎么变的：`v1→vN` 时间轴，节点标状态与**间隔天数** |
| **星网** | 有哪些项目：项目列 → 话题分组 → 条目，可三层折叠、按类别 tag 筛选 |
| **冲突** | 哪两条在打架：新旧全文 + 判定理由 + 三个裁决按钮 |

点任意条目，右侧显示版本链、前因、相关记忆，以及从 L0 解压出来的原文片段。


## 日常维护

```powershell
& $py demo\maintenance.py check        # 结构自检（孤儿/负引用/FTS 一致性）
& $py demo\maintenance.py decay        # 权重衰减，dry-run
& $py demo\maintenance.py reclaim      # 四条回收触发，dry-run
& $py demo\maintenance.py reclaim --apply   # 真删（不可逆）
```

回收默认 **dry-run**：删原文不可逆，顺手调用不该能毁数据。保留档按材料内是否有核对过的条目分
（已核对 180 天 / 未核对 730 天）。cron 里加 `reclaim --apply` 之前，先跑一周 dry-run 看日志。

## 访问控制

看板默认**要令牌**：首次启动会在 `demo/.env` 写一行 `API_TOKEN=...`，打开 `http://127.0.0.1:8777` 会被重定向到登录页，粘贴令牌即可（服务端下发 `HttpOnly` cookie，30 天有效）。

| 项 | 现状 |
|---|---|
| 令牌来源 | 环境变量 `TB_TOKEN` > `demo/.env` 的 `API_TOKEN` > 首次启动自动生成 |
| 鉴权方式 | `Authorization: Bearer <token>` 或 `tb_token` cookie |
| 限流 | 每 IP 每分钟 120 次；连续 5 次错令牌封 60 秒 |
| 合法用户保护 | **令牌正确时不受封禁影响**（避免攻击者连坐） |
| 响应头 | `X-Content-Type-Options` / `Referrer-Policy` / `X-Frame-Options` |
| CORS | **不发任何 `Access-Control-Allow-*`**，只允许同源 |
| 绑定地址 | 默认 `127.0.0.1`；要开给手机需自己改，且**必须走 HTTPS 反代** |

**不是**：单令牌、没有用户体系、没有审计日志、没有 TLS。放公网前必须再补一层。

## 它证明了什么

| # | 结论 | 证据 |
|---|---|---|
| 1 | 一份材料一个文件、条目按 offset 指回去，可行 | 3 份材料 → 3 个 `.gz`，2,818 字节存下 4,745 字原文 |
| 2 | LLM 提炼质量碾压规则版 | 带依据摘要 **14% → 94%**；条数 22 → 16（不再拆碎） |
| 3 | 冲突"只挂起不自动执行"能落地 | 检出 ≥1 处覆盖，新条目转 `pending_merge`，等人裁决 |
| 4 | 版本链能表达"改口"，且**间隔本身就是信号** | 四版链：+31 / +61 / +92 天，间隔在拉长＝决策在收敛 |
| 5 | 补充记忆不会动到原有记录 | 前后快照逐条比对：**0 条**状态/版本/摘要变化 |
| 6 | 概念层能把跨话题的记忆捞到一起 | 问「咖啡车生意」→ 30 条，跨 4 个类别 |
| 7 | LLM 的不确定性可以被"重放"消除 | 两次运行 122 行日志逐行一致；21.5 s → 0.25 s |
| 8 | 降级路径（规则版）能收敛，不会灌垃圾 | 叙事文本 1.4 万字：175 条 → **32 条**；业务材料 22 → 20 条，冲突与链条不受影响 |
| 9 | **断网也能写入** | 模拟断网：20 条 **15 ms** 落库，全部 `provisional`，检索照常可用 |
| 10 | 精修异步、且会拒绝劣化 | 扫描 8 条 → 采纳 7、**驳回 1**（丢事实）；每次替换都留痕在 `memory_revisions` |
| 11 | 对话开头能主动浮现 | 3 条，按话题去重，每条带“为什么是它”（权重/新鲜度/改过几版） |
| 12 | Markdown 单文件可读可改 | 导出 20 条；人工改一行 → `rebuild_from_markdown` 后能搜到 |

## 它没做什么（截至今天）

| 缺口 | 影响 |
|---|---|
| **衰减 / 硬归档 / TTL 回收** | L0 只增不减。四篇小说的语料就有 20 KB，长期会撑大 |
| **维护 CLI（cron 入口）** | 回收、对账只能手工调函数 |
| **API 鉴权 / 限流** | 看板只能绑 `127.0.0.1` |
| 评估集与指标 | 没有 Recall@10 之类的硬指标 |
| 向量检索 | 测过 LSA：概念挂靠 50% vs bigram 50%，**没证明自己**，暂缓 |
| 音频 / Obsidian 导出 / 数据迁移 | 方案里已列为非必要功能 |

## 写入与增强是两条路

| 阶段 | 做什​么 | 联网 | 耗时 |
|---|---|---|---|
| **写入** | 落 L0、规则提炼、入库（`extract_state=provisional`） | **不需要** | 十几毫秒 |
| **精修** | LLM 把摘要改写成「结论——依据」，失败则保持原样 | 需要 | 每条一次调用 |
| **向量** | 未实现（方案里是预留设计） | — | — |

断网时只有第一段发生——**记忆不会因为网络挂掉而丢**。精修随时可补，且每次替换都在 `memory_revisions` 留痕。

## 已知短板（都是实测出来的）

| 现象 | 原因 |
|---|---|
| 规则提炼靠阈值筛人，会漏掉叙事文本里的细节（小说语料里查「长衫」0 条） | 它判断不了"值不值得记"，只能判断"有没有信号"；要细节得走 LLM 路径 |
| 规则提炼把小说句子硬掰成"结论——因为依据" | 提示词按工作记录设计，换语料要换 profile |
| 冲突配对靠字面重合，换了说法就配不上 | 候选召回没有语义能力；已用"言语行为分类"缓解，未根治 |
| 概念自动挂靠 accuracy 只有 50% | 只能人搭骨架、机器挂靠高置信的部分 |
| 简繁字表覆盖约 15%，生僻异体不保证 | 498 对高频字；缺失字原样保留，**只漏检不出错** |
| 样例数据的时间是按原文位置铺出来的 | 材料本身跨月，写入却是同一秒 |

## 脚本

| 脚本 | 干什么 |
|---|---|
| `tb.py` | 核心：建库、L0 落盘、分块、提炼、写入、检索、取原文、版本链、冲突、概念 |
| `llm_ingest.py` | LLM 提炼（`extract_llm`）+ LLM 冲突判定（`judge_llm`） |
| `run_demo.py` | 八步走查（环境/建库/①L0/②提炼/③检索/④原文/⑤归档/⑥冲突/⑦版本链/⑧星网） |
| `run_complement.py` | 补充记忆：只加信息，验证原有记录 0 改动 |
| `run_offline.py` | 断网写入 → 联网精修 → 主动浮现 → Markdown 往返，四段自证 |
| `selftest.py` | 12 项不变量断言 |
| `maintenance.py` | 维护 CLI：`stats` / `decay` / `reclaim` / `check`（默认 dry-run） |
| `run_maintenance.py` | TTL 回收自证：分档、dry-run、幂等、账目 |
| `run_eval.py` | 评估：检索 Recall/MRR + 冲突判定 P/R/F1（自带可复现语料） |
| `web.py` | 看板：搜索 / 演变 / 星网 / 冲突 |
| `api_client.py` | OpenAI 兼容客户端 + record/replay 缓存 |
| `compare_extract.py` · `compare_search.py` | 规则 vs LLM 的提炼与检索对照 |
| `concept_probe.py` · `vector_probe.py` | 概念挂靠阈值标定；bigram vs LSA |
| `probe_extract.py` | 规则提炼的分数分布（看阈值该定在哪） |
| `test_review.py` | 走 API 验一遍人工裁决：取待裁决 → POST 裁决 → 看版本链 |
| `t2s.py` | 繁→简对照表（498 对），分词入口调用 |
| `demo_util.py` | 共用输出工具 |
| `corpus/` | 压力测试语料（鲁迅《呐喊》四篇，公版） |

**改完代码的固定动作**：`run_demo` → `run_complement` → `selftest`。三步都绿再谈别的。

## 换成正式实现要改哪里

| 现在 | 换成 |
|---|---|
| `extract()` 规则提炼 | LLM 调用（契约见手册 6.6）——**已做，`llm_ingest.py`** |
| `tokenize()` bigram | 装 jieba 后自动启用，调用方不用改 |
| `compress()` gzip | 装 zstandard 后自动启用 |
| `search()` 纯 FTS | 加向量路 + RRF 融合（等模型可用再评） |
| 无 TTL | 补齐 8 章的四个回收触发 |
